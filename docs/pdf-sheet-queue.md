# PDF 시트 자동 다운로드

기존 큐 스프레드시트에 `pdfs` 탭을 사용합니다. `/pdf` 화면의
**PDF 전용 시트 열기**로 이동한 뒤 A2부터 URL을 한 줄에 하나씩 입력하세요.
웹앱의 여러 URL 입력창이나 Link Gopher의 선택 항목도 이 탭에 추가됩니다.

| 열 | 필드 | 사용 방법 |
| --- | --- | --- |
| A | url | 필수: 파일 또는 설명/미러 페이지 URL |
| B | folder | 선택: 저장 폴더 이름, 기본 PDF (경로에서는 소문자 pdf) |
| C | expected_md5 | 선택: 원본 파일 지문. URL에 있으면 자동 확인 |
| D | status | 자동 처리 상태 |
| E–H | filename, local_path, file_id, md5 | 다운로드 결과 |
| I | error | 실패 원인 |
| J | updated_at | 로컬 컴퓨터 기준 마지막 기록 시각 |
| K | source_page | 선택: 파일을 찾은 게시물·목록 주소 |
| L | title | 선택: 페이지에 표시된 파일명·제목 |

K·L은 기존 시트의 A–J 열을 그대로 유지하면서 추가된 메타데이터입니다.
새 링크 찾기 화면은 이 값을 함께 저장해 서버의 원래 파일명을 알 수 없을 때도
사람이 선택한 이름으로 저장할 수 있게 합니다.

`python app.py`로 앱을 실행하면 PDF 워커가 자동으로 시작합니다. 다른 이미지
워커는 기존처럼 수동 시작합니다. PDF 워커는 한 번에 하나씩 처리하고, 한 차례
처리가 끝나면 10초 후 시트를 다시 읽습니다. 새 URL은 빈 status 또는 `pending`
상태여야 합니다. `downloading` → `downloaded` 또는 `failed`로 바뀝니다.
실패한 행은 원인을 해결한 뒤 D열을 `pending`으로 바꾸면 다시 처리합니다.

**지금 처리** 버튼은 자동 확인 간격을 기다리지 않고 시트를 즉시 읽어 대기
링크를 한 번 처리합니다. 자동 처리가 꺼져 있어도 동작하며, 이미 처리 중이면
중복 실행하지 않습니다. Google 시트에 수정 내용이 저장된 뒤 눌러주세요.

**자동 실행**과 **자동 정지**는 별도 버튼입니다. 자동 실행은 지속적인 시트
확인을 켜고, 자동 정지는 현재 파일 처리 후 멈춥니다. 현재 상태에 맞는 버튼만
활성화되며, **지금 처리**는 한 번 실행하는 독립 버튼으로 유지됩니다.

이 컴퓨터와 앱이 켜져 있어야 다운로드됩니다. 브라우저를 닫아도 서버가 실행
중이면 계속됩니다. `PDF_AUTO_START=0`으로 실행하면 자동 시작을 끌 수 있습니다.
웹앱에서 중지하면 현재 파일 처리가 끝난 뒤 멈춥니다. 처리 중 행 삭제·정렬은
피하세요. 서버를 강제 종료해 `downloading`에 남은 행은 저장 파일을 먼저 확인한
뒤 필요할 때만 `pending`으로 되돌리세요. 결과를 시트에 쓰지 못한 경우에도
중복 다운로드를 막기 위해 자동 재시도하지 않습니다.

다운로드는 기존 `pipeline.DOWNLOADS_DIR` 아래에 저장되며 F열에 실제 절대 경로가
기록됩니다. `/pdf`의 받은 PDF 목록에서 **파일 받기**로 브라우저에도 저장할 수
있습니다. 파일 형식 지원과 미러 제한은 [file-resolver.md](file-resolver.md)를 따릅니다.

다른 설치에서는 `queue_config.py`의 스프레드시트 설정에 맞춰 `pdfs` 탭과
`sheets.PDF_HEADERS` 순서의 첫 행을 준비하고, 기존 Google OAuth 파일을 설정해야
합니다. 인증 파일은 Git에 포함하지 않습니다. 같은 시트를 여러 앱 인스턴스에서
동시에 처리하는 분산 잠금은 지원하지 않습니다.
